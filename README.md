# Aru Retopo Tool

## ダウンロードして使う（Windows）

1. GitHubの **Code → Download ZIP** で取得し、ZIPを展開します。
2. Mayaを開き、展開したフォルダの **install.py をビューポートへドラッグ＆ドロップ**。
3. **AruRetopo** シェルフの **Retopo** ボタンから起動できます。

Windows x64用DLLを同梱しています。Maya 2024 / 2027で自動動作テストを検証済みです。
Maya 2024／2027で検証した共通の `bin/aru_retopo_core_v8.dll` と
`bin/aru_retopo_display_v3.dll` を読み込みます。Maya SDKやPython ABIには依存しません。
Aru_libや元のAru_CurveNetRigは不要です。Maya付属のPySideを使用します。
NumPyが未導入の場合（クリーンなMaya 2024など）は、インストーラーがPyPIから
ツール専用の `_deps` フォルダへ導入します。この初回導入にはインターネット接続が必要です。
Maya本体のPythonパッケージは変更しません。
更新時も同じ手順で上書きできますが、プラグインを読み込んだ状態ではDLLがロックされるため、
更新前にMayaを再起動してください。インストール直後に保存シーンの自動ロードを使う場合も一度再起動してください。
macOS/Linuxは cpp/CMakeLists.txt から各環境用ライブラリのビルドが必要です。

手動導入する場合はフォルダ名を **Aru_RetopoTool** にして Maya の scripts フォルダへ置き、
`import Aru_RetopoTool; Aru_RetopoTool.show()` を実行します。


内蔵のリトポ専用ガイドエディタで描いたカーブから、指定したメッシュの表面へ
四角形メッシュを生成する Maya ツールです。カーブ自体が浮いていても、生成頂点は参照面上に置かれます。
ガイド編集実装は `editor/` に独立して取り込み済みです。元の `Aru_CurveNetRig` の
コードを読み込まず、別の `retopoGuideNode`・コマンド・編集状態を使用します。
元ツールはそのまま併用できます。スキン／ポーズ／デバッグノードは登録しません。
四辺で囲まれた領域は、境界カーブ4本をCoons補間して内部の流れにも反映します。
その後に参照面への投影と頂点整列を行います。三辺・五辺以上の領域は従来の
Catmull-Clark方式を使い、接続と頂点番号はどちらも維持します。

編集中はC++で計算した頂点・面データを常設のGPUロケーターで表示します。
通常のメッシュシェイプは「通常メッシュとしてコピーを確定」を押したときだけ作成します。
Maya 2024／2027用のプラグインは `bin/2024`／`bin/2027` にあります。
更新後はインストーラーを再実行してMayaを再起動すると、保存シーンからも対応版を読み込めます。
これはメッシュ計算の高速化であり、編集全体の60fpsを保証するものではありません。

## 対称編集・ブラシ・ソフト移動

- 左右反転はカーブと面張り済みのパッチを一緒に反転します。未確定の領域には面を作りません。反転先を置換する場合、面張り状態も反転元に合わせます。1回のUndoでカーブと面張り状態を戻せます。
- 対称面上のEPを動かすときは中心に沿って移動します。両端が中心にあるカーブはハンドルも中心に拘束し、リラックス後も維持します。中心から横へ伸びる枝のハンドルは通常どおり編集できます。
- ガイドと面の編集ツールで **B＋中ドラッグ（左右）** によりブラシ半径を変更します。黄色い円が範囲、ポイント周囲の色付きリングが影響の強さです。Shiftのリラックスとソフト移動で共通の半径を使います。
- **ソフト移動** をONにしてEPを中ドラッグすると、周囲のEPと接線も減衰付きで動き、参照メッシュの表面に沿います。影響範囲は掴んだ時点で固定します。対称側も同期し、接続は変更しません。Escで移動を取り消せます。ハンドル単体の編集は従来どおりです。
- **単点移動で自動マージ・カーブ接続** は初期状態でOFFです。ON時の接続距離は隣のpx設定（初期12px）で調整し、Bで変更するブラシ半径とは独立しています。ソフト移動中の自動接続はありません。意図的なカーブ作成・Shiftクリックによる接続操作は利用できます。

更新後はMayaを再起動して描画プラグインも読み直してください。

## 通常起動の高速構成

`Aru_RetopoTool.show()` で、C++差分更新・GPUの面/エッジ/カーブ/ポイント表示・高速なカーブ選択を有効にします。テスト用モードの切り替えは不要です。GPU投影の試作は通常経路では使いません。CUDAのインストールも不要です。

ロケーターはシーンに保存され、ツール切り替え・Undo/Redo・保存で作り直しません。ガイドまたはロケーターを選択して「選択から読み込み」で編集を再開できます。新規シーンや別のシーンを開いた後は、通常どおりツールを起動してください。「最前面表示」を外すと通常の深度判定に戻ります。旧版シーンの変換・移行処理はありません。

更新後はMayaを再起動してください。旧版の更新プラグインがロード済みの場合は同じノード型を置き換えられないため、新しいMayaで、保存シーンを開く前にツールを起動します。2024/2027用の差分更新・表示・選択バイナリを同梱しています。

参照面への投影では、前回の投影先が引き続き最寄りだと判定できるときに三角形探索を省略します。判定できない場合は通常の探索を行います。通常起動はこの処理を含む `aru_retopo_mesh_buffer_certified.mll` を使います。再ビルドは `cpp/build_interactive.ps1 -MayaVersion 2024`（または `2027`）で行えます。 ブラシの表裏・遮蔽判定はメインスレッド上のC++一括呼び出しを使い、法線以外の不要な付着情報を生成しません。専用DLLの再ビルドは `cpp/build_maya_visibility.ps1 -MayaVersion 2024`（または `2027`）です。遮蔽判定DLLも起動時に検証し、欠落・不一致はエラーとして通知します。

EPのリラックスは投影・法線・近傍平均・再投影をC++でまとめて処理し、ブラシ対象とその隣接点だけを渡します。標準投影DLLは `aru_retopo_maya_projector_compact.dll` です。 トポロジー変更時の細分化接続・パッチ座標・隣接情報を共通C++ ABI 8で生成し、細分化係数もC++内に保持して最終配列までまとめます。更新時はMayaを再起動してください。起動時に現行DLLの必須APIを検証します。DLLの欠落・世代不一致は明示的なエラーとし、旧DLLやPython版への暗黙の切り替えは行いません。交点フィットの数値安定性のためのSVD処理、共有ハンドル、ハードサーフェース用の処理は維持しています。再ビルドは `cpp/build_maya_projector.ps1 -MayaVersion 2024`（または `2027`）です。

交点ハンドルの長さ調整も、正則化した2変数解法と行列構築をC++でまとめています。旧DLLや正規化されていない接線では従来のSVD経路へ戻ります。SVDとの丸め差はありますが、検証GUIではメッシュ座標差が最大約6.7×10⁻¹⁶、描画用float32座標は一致しました。

500パッチ・46,528面のMaya 2027比較では、同じ入力・カメラ・1600×1000表示で、リラックスが従来の約58〜60msから約37.6〜38.7ms、ポイントドラッグが約29.5msから約26.7msになりました（中央値、描画込み、最初のブラシは443 EPに作用）。実際の編集ハンドラーをスクリプトで実行した計測で、物理マウス操作の遅延とは異なります。60fpsは未達です。「最前面表示」OFFではガイドが通常のPython描画に戻り、表示負荷が増えます。

Mayaの評価モードは DG／Serial／Parallel で動作確認しています。計算ノード自体は `kSerial` とし、その内部のC++処理を並列化しています。GPU表示はViewport 2.0の独自描画で、Maya標準のGPU Overrideによる計算のGPU化ではありません。

## 常設ロケーター表示と編集復帰

編集中の通常メッシュと一時表示の二重構成を廃止しました。面・エッジは生成ノードごとに1つの常設ロケーターへ表示し、確定コピーだけが通常メッシュになります。元のロケーターはそのまま編集できます。
カーブ編集へ戻るたびに面張り・Shift＋中クリックによる解除を再接続します。ウィンドウを開き直しても選択中のガイド／ロケーターの生成ノードを再利用します。
近接ズームで面が欠ける原因だった画面距離依存の補正上限も取り除き、参照形状の大きさで深度補正を制限します。形状データは変更しません。

## 2026-09-18 実地確認用の更新

参照メッシュによるガイド・ポイント・生成面の遮蔽を修正しました。
シリンダーでMaya 2024 / 2027の透視・平行投影を確認しています。
領域検出・細分化計画・ガイドとCoons補間係数をC++で生成し、確定済みパッチの引き継ぎ処理も整理しました。
500パッチ・約4.6万面のMaya 2027で同じ操作を交互に比較し、接続変更を伴うポイント確定は領域検出のC++化前後で中央値約373msから296ms、平均約354msから316msへ短縮しました。
頂点座標・面接続の完全一致とUndoによる復元を確認しています。スクリプトから実編集ハンドラーを呼んだ計測で、物理マウス操作の遅延とは異なります。
本体v8での最終確認では、接続を変えないポイント移動の確定が約60ms、接続変更を伴う確定が約299msでした。接続変更時は全体の再構築が必要なため、通常の位置移動より待ち時間が残ります。

**更新後はMayaを再起動してください。** `bin/aru_retopo_core_v8.dll` が必要です。
以前のDLLを読み込んだMayaでPythonモジュールだけを再読み込みしないでください。

## 起動・操作

```python
import Aru_RetopoTool
Aru_RetopoTool.show()
```

メニューは **Aru Tools → モデリング → カーブガイド・リトポロジー**。
既存セッションでは **メニュー管理 → メニューを再読み込み** を実行してください。
`DCC/settings/maya/Aru_RetopoTool.mod` を追加しているので、指定の `maya.bat` からの次回起動では
保存シーンが要求するRetopoプラグインも検出できます。

1. 追従先を選択し「参照メッシュ」の「選択から設定」。
2. 「新規ガイド」を押し「ガイドと面を編集」で統合コンテキストへ入ります。
   左クリックでガイドを描き、ポイント上の中ドラッグで移動、Shift＋左ドラッグでリラックス。
   パッチ上の中クリックで面を確定できます。ガイド編集と面張りの切り替えは不要です。
   既存CurveNetは選択して「ガイドをコピーして取り込み」。元のオブジェクトは保持します。
3. 細分化レベルを設定し「面張りツールを開始」。初期値2から試してください。
4. パッチ上をホバーすると半透明のプレビューを表示し、中クリックで面を確定します。
   Shift＋中クリックで解除、Qで終了。確定・解除はUndoできます。
   カーブを描いただけでは面は作られません。確定済みの面だけがガイド移動へ追従します。
   境界の削除・分割などでパッチの接続が変わった場合は、改めて面を確定してください。
5. ガイドまたは生成ロケーターを選択して「選択から読み込み」で設定を再編集できます。
6. 「通常メッシュとしてコピーを確定」で独立した編集可能なメッシュを作ります。
   元の生成ノード、カーブネット、参照メッシュは維持されます。

参照メッシュの表示は変更しません。生成プレビューは不透明な色付きの面＋エッジ表示です。
「最前面表示」は初期状態でオンです。通常起動のGPU表示では参照メッシュの深度を保持し、
表面付近の面・エッジ・ガイドだけを少し手前に描画します。参照メッシュの裏側にある
カーブやハンドルは隠れます。カメラ距離によって手前への補正が大きくなりすぎないよう、
参照メッシュの大きさでも補正量を制限します。これは表示専用で、頂点座標や投影結果を変更しません。
確定コピーには表示専用のオーバーレイを残しません。ビューポートでLocator表示を無効にした場合は
オーバーレイも非表示になります。
生成メッシュはワールド座標で出力するため、プレビューの移動・回転・拡縮をロックし、
親トランスフォームを継承しません。確定コピーでは移動・回転・拡縮のロックが外れます。

「ガイドの影響」は表面上での頂点整列に対するガイド位置の保持率です。
1でガイドを投影した位置を保持、0でガイド上の頂点も隣接頂点と均します。
整える回数が0の場合、この設定による差はありません。

カーブの追加・削除と細分化レベル変更では接続を再構築します。
位置編集では接続と頂点番号を保持します。分岐順を変えるような大きな編集後には
「領域を再検出」を実行してください。
球を回り込むネットで外周まで閉じた面候補になる場合、候補群が閉殻を作り、
最大の周長が次点の1.5倍を超えるときは、その最大領域を外周として除外します。
これは開いたリトポ領域向けの推定です。大きな面を含む完全な閉殻とは自動で区別できません。

## コンテキスト内でドラッグ押し出し

「ガイドと面を編集」中、境界カーブを **Ctrl＋中ボタンで掴んでドラッグ** します。
対象EPは緑、押し出し先のカーブとEPは黄色で表示されます。参照メッシュの表面へ
投影しながらプレビューし、ボタンを離すと確定、Escで取り消します。
Ctrlを押して境界に合わせるとループ全体が緑になります。中ドラッグでそのループを押し出します。
開いた境界は分岐のない一続きのカーブが対象です。
「Ctrl＋中ドラッグの押し出しで面も作成」で面の同時作成を切り替えられます。
確定後は新しいEPを選択するので続けて押し出せます。1回のUndoで一段戻せます。
統合コンテキストではCtrl＋中ボタンを押し出しに割り当てています。

## 輪切りと境界の押し出し

「輪切りの設定・境界の押し出し」から専用ウィンドウを開きます。
輪切りは点数（3〜128）、ワールド軸、メッシュ中心からの位置、ポイント配置の回転を指定し、
プレビュー後も数値を調整できます。点数・配置回転・位置の値は記憶され、
Ctrl＋左ドラッグの輪切りにも反映されます。既存ガイドとの交差には追加のEPが入ります。

押し出しは境界EPを選びます。1点の選択なら分岐のない境界全体、複数点ならその間の
連続した範囲が対象です。ワールドXYZ方向と符号付き距離で一段押し出し、参照面へ投影します。
「押し出した帯の面も確定」を切るとガイドだけを追加できます。
プレビューを確認してビューポートの中クリック（または確定ボタン）で確定します。
Q／キャンセル／ウィンドウを閉じるとプレビューを破棄。確定は1回のUndoで戻せます。

### 境界間のブリッジ

「輪切り・押し出し・ブリッジ」を開き、作成方法を「境界間をブリッジ」にします。
片側の境界EPを選んでAへ登録し、反対側を選んでBへ登録します。
1点なら分岐のない境界全体、複数点なら連続した選択範囲を使います。
同じ点数の閉じたリング同士、または開いた境界同士に対応します。
点数が違う場合はA/Bそれぞれの点数を表示して確定を止めます。

登録時は近いポイント同士へ自動で対応を合わせます。プレビューしながら
「接続位置をずらす」（リングのみ）と「Bの向きを反転」で対応を調整できます。
中クリック／確定ボタンで接続カーブを作成し、「作成した帯の面も確定」がオンなら
帯状の面も作ります。元のポイントは移動しません。ガイドの接続を編集した場合は
A/Bを登録し直してください。

## 実装

- `core.py`: 接線と参照面法線による領域検出、共有境界、Catmull–Clark型の細分化計画。
- `cpp/retopo.cpp`: C++17 / BVH最近傍投影、細分化の重み付き和、反復整列と再投影。
- `native.py`: ctypesによるC ABI接続。Maya SDK・Python ABIへのリンクは不要。
- `aru_retopo_plugin.py`: `aruRetopoMesh` DGノード。`outNetData` と `worldMatrix`、
  参照メッシュの `worldMesh` を入力し `outMesh` を出力。シーンに接続と設定を保存。
- `preview_locator.py`: 常設GPUロケーターの所有と接続。編集中は通常メッシュを生成しません。
- `maya_api.py`, `ui.py`: Undo対応の生成・設定・確定コピー、Maya所有のウィンドウ。

OpenSubdiv本体はリンクしていません。Catmull–Clarkの基本的な面・辺・頂点の規則を使う
独自実装に、Bézierガイドのサンプリングと参照面への投影を組み合わせています。
そのためOpenSubdivの極限曲面との一致を目的とするものではありません。
5角形は初回で5枚、レベル2で20枚、レベル3で80枚の四角形になります。
上限は1ノード20万面です。

投影先の形状が同じならC++のBVHを再利用します。カーブの位置編集では細分化計画を再利用します。
参照形状の取得・比較、生成メッシュのMayaデータ化、初回の接続計画はPython側です。
したがって、非常に重い参照メッシュではこの部分もボトルネックになり得ます。

## 現バージョンの範囲

- 接続された3辺以上の閉領域が必要です。見た目だけ交差したカーブは交点として扱いません。
- 4辺だけでなく3・5・6辺などにも対応します。非4辺領域の中心にはポールができます。
- 多角形の中心を囲む分割が基本です。強い凹形状、穴を含む領域、大きく折り返した領域で
  最適な流れを自動探索する機能はありません。補助ガイドで小さい領域に分けてください。
- 投影の安定化は前回の三角形の接続成分と法線方向を使います。
  薄い形状での裏面への飛び移りを軽減しますが、同じ接続成分内で同方向の面が近接する場合まで
  防ぐ局所的な測地線追跡ではありません。初回は最近傍投影です。
- 参照メッシュのトポロジー変更時は投影履歴をリセットします。
- 頂点は参照面上にありますが、粗い四角形の面内部まで曲面に一致するわけではありません。
  曲率が高い部分は細分化レベルを上げてください。
- カーブごとの異なる密度、ポールの手動移動、UV生成、任意の疎なガイドからの全面自動リトポは未実装。
- インスタンス入力は対象外。通常の複製を入力してください。
- ノードID `0x00131AD0` はローカル開発用。外部配布する場合は正式に予約したIDに置換してください。

## ビルド

Windows x64向けDLLは `bin/aru_retopo_core_v8.dll` と `bin/aru_retopo_display_v3.dll` に配置します。
Visual Studio 2022 C++ Build Tools と Windows SDK があれば:

```powershell
& ./cpp/build_windows.ps1
```

## 対称編集の対応範囲

ガイド編集設定の対称軸（X/Y/Z）と空間（参照メッシュのローカル／ワールド）を使います。

| 操作 | 対応 |
| --- | --- |
| EP・カーブ作成、ポイント／ハンドル移動、分割・結合、Shiftリラックス | 既存の対称処理を維持 |
| 境界のドラッグ押し出し・数値指定押し出し | 対称側の帯とガイドも生成 |
| ブリッジ | 対称側の接続と面も生成 |
| 輪切り（ドラッグ・設定ウィンドウ） | 対称側にも生成。重なる切断面は1つの対称ループに統合 |
| 面のホバー・確定・解除 | 対応する対称パッチを同時に操作 |
| Ctrl＋ShiftクリックのEP／カーブ削除、選択EPの削除 | 対称側も削除 |

既存の対応するEP・カーブは再利用します。面張りは対称側にも対応パッチがある場合に適用します。
輪切りは対称性を維持するため指定数よりEPが増える場合があります。

## キューブなどのハードサーフェース

「参照メッシュの稜線からガイドを追加」で、面の角度差が35度以上の稜線と開いた境界を
直線ガイドにします。キューブなら8つの角・12本の稜線です。既存の同一ガイドは重複しません。
面は自動作成されず、従来どおり中クリックでパッチを指定します。

「ハードサーフェース」を有効にすると、表面上に収まる区間は直線としてフィットし、
輪切りの角にEPを追加します。Shiftリラックスは稜線上の点を稜線に拘束し、角を固定します。
輪切りのEP数は角を保つため指定数より増える場合があります。
角をまたぐ滑らかな1本のカーブを完全な折れ線にはできないため、既存ガイドには角のEPを
追加するか稜線ガイドを使用してください。モードは作成・フィット時に作用します。


## ガイド表示と面の分割

ガイドのX線表示が有効な場合、カーブ・EP・ハンドルは最前面の画面描画になります。
生成面と同色でも判別できるよう、カーブに暗い縁取りを付けています。形状の座標は変更しません。

面を張った領域の境界カーブを分割したり内部にカーブを追加した場合、子パッチへ面の確定状態を
引き継ぎます。隣接する未確定領域は未確定のままです。分割と面の引き継ぎは同じUndoで戻ります。
既に旧版の編集で確定状態が失われた領域は、元の境界情報がないため面を指定し直してください。
